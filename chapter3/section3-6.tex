\section{Kết quả kiểm thử}

Phần này ghi nhận kết quả sau khi áp dụng chiến lược kiểm thử đã nêu ở Chương 2. Nội dung tập trung vào bằng chứng đạt/không đạt, không lặp lại chi tiết thiết kế của engine, API, cache, RBAC hoặc Docker Compose.

\subsection{Tổng quan kết quả}

Các nhóm kiểm thử chính đều hoàn thành với kết quả đạt. Rule Evaluation Engine trả về đúng precedence và reason code; Backend API giữ contract response ổn định; mutation tạo audit log và invalidation cache như kỳ vọng; Dashboard phản ánh đúng quyền thao tác; Demo Application nhận kết quả từ SDK và thay đổi giao diện theo trạng thái flag.

\subsection{Rule Evaluation Engine}

Unit test xác nhận các nhánh quyết định quan trọng: archive, disabled, group kill switch, flag kill switch, global on, user allowlist, role targeting, percentage rollout, default off, \texttt{NOT\_FOUND}, \texttt{INVALID\_CONTEXT} và \texttt{ERROR}. Kết quả cho thấy engine luôn dừng ở điều kiện có precedence cao nhất và không đánh giá các rule thấp hơn khi đã có kết quả terminal.

Đối với percentage rollout, cùng một \texttt{targetingKey} luôn được ánh xạ tới cùng một bucket khi cấu hình không đổi. Khi tăng tỷ lệ rollout, tập người dùng đã được bật tiếp tục được giữ lại; khi giảm tỷ lệ, chỉ các bucket nằm ngoài ngưỡng mới bị tắt.

\subsection{Backend API và persistence}

Integration test xác nhận các API quản trị xử lý đúng dữ liệu hợp lệ, từ chối dữ liệu sai định dạng và phân biệt được các tình huống \texttt{NOT\_FOUND}, conflict và validation error. Evaluation API luôn trả response an toàn với \texttt{enabled = false} cho các trường hợp không thể đánh giá.

Các mutation quan trọng đều tạo audit log append-only với actor, action, request ID và snapshot trước/sau. Các kiểm thử cũng xác nhận dữ liệu audit không bị sửa hoặc xóa thông qua API quản trị thông thường.

\subsection{Cache, statistics và RBAC}

Cache test cho thấy request đầu tiên tải snapshot từ cơ sở dữ liệu, các request sau dùng cache, và cache liên quan được invalidation sau mutation. Khi cache lỗi, Evaluation API fallback về repository và vẫn giữ kết quả fail-closed đúng contract.

Statistics test xác nhận số lần evaluation được tổng hợp theo flag, kết quả bật/tắt và mốc thời gian phục vụ Dashboard. RBAC test xác nhận ba vai trò demo hoạt động đúng: admin có toàn quyền, developer chỉ được phép trong phạm vi cấu hình được cấp, viewer chỉ đọc. Các thao tác vượt quyền bị chặn ở backend và được phản ánh trên Dashboard.

\subsection{Dashboard, Demo Application và Docker Compose}

Kiểm thử giao diện xác nhận Dashboard hiển thị đúng danh sách project/flag/rule/group, trạng thái lifecycle/runtime, audit log, statistics và trạng thái vô hiệu hóa theo role. Demo Application gọi Evaluation API thông qua JavaScript SDK, hiển thị tính năng theo kết quả \texttt{enabled} và dùng fallback tắt khi API không khả dụng.

Quy trình Docker Compose build và khởi chạy thành công các thành phần chính gồm PostgreSQL, Backend API, Admin Dashboard và Demo Application. Sau migration và seed, hệ thống có dữ liệu demo đủ để trình bày các kịch bản end-to-end mà không cần cấu hình thủ công ban đầu.
