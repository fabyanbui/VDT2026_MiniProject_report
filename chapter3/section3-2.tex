\subsection{Quản lý project và environment nội bộ}

Backend hỗ trợ quản lý project và sử dụng environment làm phạm vi cấu hình/evaluation. Environment xuất hiện trong schema, seed data, repository và Evaluation API; Dashboard hiện chưa mở màn hình CRUD environment riêng.

\subsubsection{Kết quả triển khai API project}

API project cho phép tạo, cập nhật, liệt kê và truy vấn project theo khóa định danh ổn định. Các ràng buộc dữ liệu được kiểm tra ở DTO và database.

\subsubsection{Kết quả triển khai environment trong repository và evaluation}

Repository truy xuất cấu hình theo project key và environment key, giúp cùng một flag có thể có trạng thái khác nhau giữa staging và production.

\subsubsection{Environment mặc định}

Seed data tạo sẵn environment mặc định để demo có thể chạy ngay sau migration/seed mà không cần cấu hình thủ công.

\subsubsection{Validation và ràng buộc dữ liệu}

Backend chuẩn hóa lỗi validation và giữ các ràng buộc duy nhất ở tầng database để tránh trạng thái trùng khóa.

\subsection{Quản lý Feature Flag}

API Feature Flag đã đáp ứng các thao tác chính: tạo, truy vấn, cập nhật thông tin, archive/restore và cập nhật cấu hình theo environment.

\subsubsection{Tạo và truy vấn Feature Flag}

Khi tạo flag, backend kiểm tra project tồn tại và khóa flag chưa bị trùng trong project. API truy vấn trả về dữ liệu đủ cho Dashboard hiển thị danh sách và chi tiết.

\subsubsection{Cập nhật thông tin flag}

Các trường mô tả được cập nhật qua endpoint quản trị và được ghi nhận audit log.

\subsubsection{Archive và restore flag}

Archive/restore được triển khai như thay đổi trạng thái vòng đời thay vì xóa vật lý, giúp giữ lịch sử cấu hình.

\subsubsection{Quản lý cấu hình theo environment}

Cấu hình runtime như enabled, serving mode và kill switch được lưu theo environment, hỗ trợ demo staging/production.

\subsection{Quản lý rule và flag group}

Backend cung cấp endpoint thay thế rule set, đổi priority và quản lý group kill switch. Cách triển khai tập trung rule mutation giúp audit và cache invalidation nhất quán.

\subsubsection{Rule user allowlist}

Rule allowlist lưu danh sách user ID trong parameters và được validation trước khi lưu.

\subsubsection{Rule role targeting}

Rule role targeting lưu danh sách role hợp lệ, phục vụ kịch bản demo theo nhóm người dùng.

\subsubsection{Rule percentage rollout}

Rule percentage rollout lưu tỷ lệ phần trăm trong khoảng hợp lệ và giao phần quyết định bucket cho engine.

\subsubsection{Quản lý độ ưu tiên rule}

Backend lưu priority cho rule cùng loại; engine vẫn áp dụng type precedence cố định để kết quả dễ dự đoán.

\subsubsection{Group kill switch}

Flag group và group config đã được triển khai để vô hiệu hóa đồng thời nhiều flag trong một environment.

\subsection{Evaluation API}

Evaluation API trả response thống nhất cho ứng dụng khách, bao gồm \texttt{enabled}, \texttt{reason}, \texttt{projectKey}, \texttt{flagKey} và các metadata cần thiết.

\subsubsection{Contract request/response}

Request nhận project key, environment key, flag key và context. Response không phơi bày cấu hình quản trị nhạy cảm mà chỉ trả quyết định đã được chuẩn hóa.

\subsubsection{Snapshot và cache}

Backend sử dụng snapshot cấu hình để giảm truy vấn lặp. Cache miss hoặc invalidation đều quay lại repository để lấy dữ liệu mới.

\subsubsection{Kết quả fail-closed}

Các trường hợp không tìm thấy project/flag hoặc lỗi nội bộ đều trả về kết quả tắt an toàn kèm reason tương ứng.

\subsection{Audit log và lịch sử cấu hình}

Audit log đã được tích hợp vào các mutation quản trị quan trọng và được dùng làm cơ sở cho lịch sử cấu hình.

\subsubsection{Ghi audit log cho mutation}

Các thao tác tạo/cập nhật/archive/restore flag, thay đổi rule và group kill switch đều tạo audit entry sau khi kiểm tra quyền.

\subsubsection{Lưu snapshot trước và sau}

Audit entry lưu before/after snapshot để người dùng có thể so sánh thay đổi mà không cần suy luận từ nhiều bản ghi riêng lẻ.

\subsubsection{Truy vấn và lọc audit log}

API hỗ trợ truy vấn danh sách audit log và lọc theo các trường phục vụ Dashboard.

\subsubsection{Bảo vệ audit log khỏi sửa và xóa}

Repository không cung cấp luồng sửa/xóa audit log trong ứng dụng, giữ đặc tính append-only ở tầng nghiệp vụ.

\subsubsection{Theo dõi lịch sử cấu hình}

History API tận dụng audit log để hiển thị chuỗi thay đổi theo đối tượng cấu hình.

\subsection{Validation và xử lý lỗi}

Backend chuẩn hóa validation, lỗi nghiệp vụ và lỗi ngoài dự kiến để client nhận được phản hồi nhất quán.

\subsubsection{Validation DTO}

DTO kiểm tra định dạng key, kiểu dữ liệu và giới hạn giá trị trước khi request đi vào service.

\subsubsection{Chuẩn hóa phản hồi lỗi}

Lỗi được trả về theo cấu trúc thống nhất, giúp Dashboard hiển thị thông báo rõ ràng.

\subsubsection{Request ID}

Request ID được dùng để liên kết phản hồi lỗi, audit log và quá trình debug.

\subsubsection{Xử lý lỗi toàn cục}

Exception filter toàn cục tránh rò rỉ stack trace và chuyển lỗi ngoài dự kiến thành phản hồi an toàn.

\subsection{Phân quyền người dùng quản trị}

RBAC demo đã được triển khai ở backend để bảo vệ endpoint mutation và cung cấp trạng thái quyền cho Dashboard.

\subsubsection{Permission matrix tập trung}

Permission matrix định nghĩa quyền theo role ở một nơi, tránh lặp logic phân quyền trong nhiều controller.

\subsubsection{Bảo vệ mutation endpoint}

Guard kiểm tra actor và quyền trước khi cho phép ghi dữ liệu.

\subsubsection{Phản ánh quyền trên Dashboard}

Backend trả thông tin role/permission để Dashboard hiển thị trạng thái phù hợp.

\subsubsection{Kết quả xử lý truy cập không hợp lệ}

Request thiếu quyền bị từ chối bằng lỗi chuẩn hóa và không tạo mutation/audit sai lệch.

\subsection{Cache và evaluation metrics}

Backend đã bổ sung snapshot cache và thống kê aggregate cho Evaluation API.

\subsubsection{Cơ chế caching}

Cache lưu snapshot theo project/environment/flag, không lưu dữ liệu context người dùng.

\subsubsection{Cache invalidation}

Các mutation ảnh hưởng đến evaluation đều gọi invalidation để snapshot cũ không tiếp tục được dùng.

\subsubsection{Ghi nhận số lần evaluation}

Sau mỗi evaluation, backend ghi nhận thống kê aggregate theo flag, environment, reason và kết quả bật/tắt.

\subsubsection{Truy vấn dữ liệu thống kê}

Dashboard sử dụng API statistics để hiển thị tổng số lượt evaluation, phân bố theo flag và xu hướng theo thời gian.
