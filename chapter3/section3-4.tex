\section{Kết quả xây dựng Demo Application và SDK}

Demo Application và JavaScript SDK được triển khai để chứng minh cách một ứng dụng web tiêu thụ Evaluation API. Phần này mô tả kết quả tích hợp thay vì lặp lại thiết kế engine.

\subsection{Cấu trúc Demo Application}

Demo Application mô phỏng một trang thương mại điện tử nhỏ với các khu vực giao diện chịu ảnh hưởng bởi Feature Flag.

\subsubsection{Mô hình ứng dụng thương mại điện tử mẫu}

Ứng dụng có các thành phần như danh sách sản phẩm, khuyến mãi, checkout hoặc banner thử nghiệm để minh họa tác động của flag.

\subsubsection{Dữ liệu người dùng và organization}

Demo cung cấp một số người dùng mẫu với role và organization khác nhau để kiểm tra các kịch bản targeting.

\subsubsection{Các tính năng được kiểm soát bằng flag}

Mỗi tính năng demo tương ứng với một flag đã seed, giúp người xem thay đổi cấu hình ở Dashboard và quan sát kết quả ở ứng dụng.

\subsubsection{Môi trường staging và production}

Ứng dụng có thể gửi environment key khác nhau để minh họa cùng một flag nhưng cấu hình khác giữa môi trường.

\subsection{JavaScript SDK}

SDK là lớp client nhỏ, typed và fail-closed, dùng lại contract của Evaluation API.

\subsubsection{Khởi tạo SDK client}

Client nhận base URL, project/environment mặc định và timeout để chuẩn bị gọi evaluation.

\subsubsection{Phương thức evaluate}

Phương thức \texttt{evaluate} nhận flag key và context, sau đó trả về response đã chuẩn hóa cho ứng dụng.

\subsubsection{Fail-closed fallback của SDK}

Nếu request thất bại hoặc response không hợp lệ, SDK trả kết quả tắt an toàn để ứng dụng không bật nhầm tính năng.

\subsubsection{Xử lý timeout và lỗi mạng}

SDK giới hạn thời gian chờ và chuyển lỗi mạng thành response fallback thay vì làm vỡ giao diện demo.

\subsection{Tích hợp SDK với Demo Application}

Demo Application gọi SDK tại các điểm cần quyết định hiển thị tính năng và cập nhật UI theo kết quả nhận được.

\subsubsection{Tạo evaluation context}

Context được tạo từ người dùng mẫu đang chọn, bao gồm targeting key, user ID, role và attributes minh họa.

\subsubsection{Gọi Evaluation API}

SDK gửi request đến backend; Demo Application chỉ nhận kết quả đã chuẩn hóa.

\subsubsection{Hiển thị hoặc ẩn tính năng}

Các component đọc trường \texttt{enabled} để hiển thị tính năng mới hoặc giữ trải nghiệm mặc định.

\subsubsection{Làm mới trạng thái sau thay đổi cấu hình}

Người dùng có thể refresh evaluation để thấy tác động của cấu hình vừa thay đổi trên Dashboard.

\subsection{User context trong Demo Application}

User context được giữ ở mức mẫu, đủ để minh họa targeting nhưng không chứa dữ liệu cá nhân thật.

\subsubsection{Targeting key}

Targeting key là định danh ổn định dùng cho percentage rollout.

\subsubsection{User ID}

User ID mẫu phục vụ allowlist và các kịch bản kiểm thử trực quan.

\subsubsection{Role}

Role mẫu phục vụ rule targeting theo nhóm người dùng.

\subsubsection{Organization trong attributes}

Organization ID nằm trong attributes để minh họa hướng mở rộng theo tenant hoặc khách hàng doanh nghiệp.

\subsubsection{Thuộc tính mở rộng}

Các attributes khác có thể được bổ sung mà không làm thay đổi contract chính của SDK.

\subsection{Hành vi fallback}

Demo Application thể hiện rõ nguyên tắc an toàn: khi không chắc chắn, tính năng mới không được bật.

\subsubsection{Evaluation API không khả dụng}

Khi backend không phản hồi, SDK trả fallback disabled và giao diện hiển thị trạng thái lỗi thân thiện.

\subsubsection{Request timeout}

Khi vượt quá timeout, request bị hủy ở phía SDK và ứng dụng tiếp tục chạy với kết quả tắt.

\subsubsection{Flag không tồn tại}

Nếu backend trả \texttt{NOT\_FOUND}, demo hiển thị tính năng ở trạng thái tắt và reason tương ứng.

\subsubsection{Context không đầy đủ}

Nếu context thiếu dữ liệu cho một rule, engine bỏ qua rule không đủ điều kiện hoặc trả reason phù hợp; demo dùng reason này để giải thích trạng thái cho người xem.
