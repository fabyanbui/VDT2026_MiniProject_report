\section{Môi trường và cấu trúc triển khai}

\subsection{Cấu trúc mã nguồn}

Mã nguồn được tổ chức theo mô hình npm workspace để tách rõ các thành phần nhưng vẫn quản lý chung trong một repository. Cấu trúc chính gồm \texttt{apps/backend} cho Backend API NestJS, \texttt{apps/admin} cho Admin Dashboard React, \texttt{apps/demo} cho Demo Application React và \texttt{packages/js-sdk} cho SDK JavaScript dùng bởi ứng dụng demo. Cách tổ chức này giúp các thành phần dùng chung quy trình cài đặt, build, kiểm thử và triển khai, đồng thời giảm rủi ro lệch API contract giữa control plane và data plane \cite{microsoft_devops,docker_compose}.

Ở Backend API, mã nguồn được chia theo module nghiệp vụ như project, feature flag, flag group, rule, evaluation, statistics, audit log, sample user và auth. Các controller chỉ tiếp nhận request và trả response; service/repository xử lý nghiệp vụ và truy cập PostgreSQL thông qua Prisma. Các phần dùng chung như validation, request context, exception filter và permission guard được đặt trong các module \texttt{common} và \texttt{auth} để tránh lặp lại xử lý ở từng endpoint.

Admin Dashboard được xây dựng theo hướng component-based với các trang project, danh sách flag, cấu hình rule, flag group, audit log và statistics. Những thành phần dùng lặp lại như badge trạng thái, dialog xác nhận, data state, history panel và API client được tách riêng để giao diện nhất quán và dễ mở rộng. Demo Application là một ứng dụng React mô phỏng storefront thương mại điện tử, đồng thời có thư mục \texttt{apps/demo/server} cho demo backend API. Frontend và demo backend cùng tích hợp SDK trong \texttt{packages/js-sdk} để đánh giá flag, kiểm tra response và áp dụng mặc định fail-closed khi API lỗi \cite{openfeature_flag_evaluation}.

\subsection{Môi trường phát triển}

Toàn bộ hệ thống sử dụng TypeScript trên Node.js. Backend dùng NestJS, frontend dùng React/Vite, còn npm workspaces quản lý các package trong \texttt{apps} và \texttt{packages}. Các lệnh phát triển ở cấp root gồm \texttt{npm run dev:backend}, \texttt{npm run dev:admin}, \texttt{npm run dev:demo}, \texttt{npm run build}, \texttt{npm run test} và \texttt{npm run lint}. Việc thống nhất công cụ giúp quá trình phát triển, kiểm thử và đóng gói các thành phần diễn ra đồng nhất.

Cơ sở dữ liệu chính là PostgreSQL, được truy cập thông qua Prisma ORM. Prisma Schema định nghĩa các bảng, khóa ngoại, chỉ mục, quan hệ và kiểu enum; PostgreSQL JSONB được dùng cho tham số rule, thuộc tính user context và snapshot before/after của audit log \cite{postgresql_json_types}. Backend bật \texttt{ValidationPipe}, Swagger/OpenAPI, CORS theo biến môi trường và exception filter để chuẩn hóa lỗi. Jest được dùng cho unit test và e2e/integration test, tập trung vào rule evaluation, cache, statistics, RBAC, persistence và các luồng demo quan trọng.

\subsection{Database migration và seed data}

Schema hệ thống nằm tại \texttt{apps/backend/prisma/schema.prisma} và được triển khai bằng Prisma Migrate. Các migration hiện có tạo và mở rộng các nhóm bảng cho project, environment, feature flag, cấu hình theo môi trường, rule, flag group, sample user, audit log và evaluation metrics. Những ràng buộc như unique key theo project, chỉ mục truy vấn, cascade/restrict relation và soft delete được khai báo trong schema để bảo vệ tính nhất quán dữ liệu.

Seed script \texttt{apps/backend/prisma/seed.ts} được thiết kế không phá hủy dữ liệu đang có: script chỉ tạo bản ghi còn thiếu và không reset các chỉnh sửa demo hiện tại. Dữ liệu mẫu bao gồm project \texttt{demo-project}, các environment \texttt{production}, \texttt{staging}, \texttt{development}, các nhóm flag dùng cho kịch bản demo, nhiều feature flag mẫu và các user mẫu đại diện cho các vai trò khác nhau. Các rule user allowlist, role targeting và percentage rollout được seed kèm audit log ban đầu, nhờ đó hệ thống có dữ liệu sẵn để kiểm thử và trình diễn ngay sau khi khởi tạo.

\subsection{Triển khai bằng Docker Compose}

Hệ thống có thể chạy bằng Docker Compose để tái tạo đầy đủ môi trường trình diễn. Tệp \texttt{docker-compose.yml} định nghĩa PostgreSQL, backend, admin, demo, \texttt{demo-staging}, các job \texttt{migrate} và \texttt{demo-seed}; ngoài ra có profile tùy chọn cho Prisma Studio và Redis. Hình~\ref{fig:docker-compose-deployment} minh họa các service chính và quan hệ phụ thuộc khi triển khai bằng Docker Compose.

Các container giao tiếp qua mạng nội bộ do Docker Compose tạo. Backend kết nối PostgreSQL bằng tên service \texttt{postgres}; Admin Dashboard và phần browser của Demo Application gọi Backend API thông qua biến \texttt{VITE\_API\_BASE\_URL}. Riêng demo backend chạy trong container \texttt{demo} gọi platform backend bằng \texttt{DEMO\_SERVER\_API\_BASE\_URL=http://backend:3000/v1}, vì \texttt{localhost} bên trong container demo không trỏ tới service backend. Service \texttt{postgres} dùng volume \texttt{postgres-data} để giữ dữ liệu sau khi container khởi động lại. Những cấu hình như database URL, cổng API, origin frontend, cache provider/TTL và token demo RBAC được đặt ngoài mã nguồn để cùng một image có thể chạy trên nhiều môi trường \cite{owasp_rest_security,docker_compose}.

\subsection{Quy trình khởi chạy hệ thống}

Quy trình khởi chạy được chuẩn hóa theo thứ tự phụ thuộc. Trên môi trường phát triển cục bộ, lập trình viên cài package bằng \texttt{npm install}, chuẩn bị biến môi trường, chạy PostgreSQL, sau đó dùng các script workspace để chạy backend, admin và demo. Với Docker Compose, PostgreSQL được kiểm tra healthcheck trước; job \texttt{migrate} chạy \texttt{prisma migrate deploy}; job \texttt{demo-seed} sinh dữ liệu mẫu; cuối cùng các service backend, admin, demo và demo staging được khởi động khi các bước trước hoàn tất. Service demo chạy Node server thay vì chỉ phục vụ static file, nhờ đó vừa serve frontend đã build vừa xử lý \path|/api/demo/*|.

Sau khi hệ thống chạy, trạng thái được xác nhận qua endpoint \texttt{/v1/health}, Swagger UI của Backend API, Admin Dashboard, Demo Application và \path|/api/demo/health|. Các kiểm tra thực tế gồm mở danh sách project/flag, xem audit log, gọi evaluation cho các user mẫu, gọi một endpoint theo mẫu \path|/api/demo/features/{featureKey}|, và bật/tắt một số cấu hình để xác nhận Dashboard, Evaluation API, SDK, demo backend và dữ liệu PostgreSQL hoạt động đồng bộ. Quy trình này giúp môi trường luôn sẵn sàng cho kiểm thử, trình diễn và đánh giá mà không cần cấu hình thủ công nhiều lần.
