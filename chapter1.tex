\section{Đặt vấn đề}

Trong phát triển phần mềm hiện đại, triển khai mã nguồn và phát hành tính năng không nên luôn diễn ra đồng thời. Một tính năng có thể đã được deploy lên môi trường production nhưng chỉ nên mở cho một nhóm người dùng nhỏ, một vai trò cụ thể hoặc một tỷ lệ người dùng nhất định. Nếu phát hành trực tiếp cho toàn bộ người dùng, lỗi nghiệp vụ, lỗi hiệu năng hoặc hành vi ngoài dự kiến có thể gây ảnh hưởng diện rộng và buộc đội phát triển phải rollback hoặc deploy lại.

Feature Flag giải quyết bài toán này bằng cách đưa quyết định bật/tắt tính năng ra khỏi mã nguồn đã triển khai. Thay vì thay đổi ứng dụng mỗi khi cần release hoặc rollback, đội vận hành có thể cập nhật cấu hình flag, rule và kill switch. Tuy nhiên, nếu các flag chỉ được quản lý rời rạc trong biến môi trường hoặc logic riêng của từng ứng dụng, hệ thống sẽ khó kiểm soát lịch sử thay đổi, khó bảo đảm kết quả nhất quán và khó mở rộng khi số lượng flag tăng.

Vì vậy, đề tài lựa chọn xây dựng một nền tảng Feature Flag thu nhỏ cho ứng dụng web. Hệ thống tập trung vào các năng lực cốt lõi: quản lý cấu hình tập trung, đánh giá flag theo context người dùng, rollout xác định, rollback nhanh, audit log và minh họa trực tiếp qua một demo application.

\section{Mục tiêu của báo cáo}

Báo cáo hướng đến hai mục tiêu chính: nghiên cứu nguyên lý Feature Flag và trình bày kết quả xây dựng một hệ thống minh họa có thể chạy được.

Về nghiên cứu, báo cáo làm rõ Feature Flag là gì, vì sao kỹ thuật này giúp tách deploy khỏi release, các loại flag phổ biến, các chiến lược rollout như global on/off, user allowlist, role targeting và percentage rollout, cũng như các yêu cầu vận hành như kill switch, audit log, caching, consistency, safe defaults và bảo mật endpoint evaluation.

Về triển khai, đề tài xây dựng một platform gồm Backend API NestJS, cơ sở dữ liệu PostgreSQL qua Prisma, Admin Dashboard React, Demo Application React và JavaScript SDK. Hệ thống cho phép tạo project, quản lý feature flag, cấu hình rule, gọi Evaluation API, ghi audit log, xem history/statistics và trình diễn các kịch bản release an toàn. Các quyết định kỹ thuật được giải thích theo hướng bảo đảm deterministic evaluation, fail-closed behavior, control-plane/data-plane separation và khả năng kiểm thử.

\section{Câu hỏi nghiên cứu}

Báo cáo tập trung trả lời các câu hỏi sau:

\begin{enumerate}
    \item Feature Flag giúp giảm rủi ro trong quy trình phát hành phần mềm như thế nào?
    \item Làm thế nào để tách việc deploy mã nguồn khỏi quyết định release tính năng cho người dùng?
    \item Một nền tảng Feature Flag tối thiểu cần những thành phần nào ở backend, dashboard, SDK, demo app và cơ sở dữ liệu?
    \item Evaluation Engine cần thứ tự ưu tiên và reason code như thế nào để kết quả bật/tắt rõ ràng, nhất quán và dễ kiểm thử?
    \item Làm thế nào để percentage rollout ổn định cho cùng một người dùng mà không lưu dữ liệu cá nhân nhạy cảm?
    \item Hệ thống cần xử lý ra sao khi project/flag không tồn tại, context không hợp lệ hoặc Evaluation API/SDK gặp lỗi?
    \item Kiến trúc và công nghệ nào phù hợp cho một mini project nhưng vẫn thể hiện được tư duy thiết kế hệ thống và khả năng mở rộng?
\end{enumerate}

\section{Phạm vi triển khai}

Phạm vi triển khai của đề tài là một Feature Flag Platform phục vụ demo và nghiên cứu, không phải một sản phẩm thương mại đầy đủ. Hệ thống được tổ chức dưới dạng npm workspace với các thành phần chính sau:

\begin{itemize}
    \item \textbf{Backend API}: cung cấp REST API cho project, feature flag, rule, flag group, evaluation, audit log, history, statistics, sample user và RBAC demo.
    \item \textbf{Rule Evaluation Engine}: đánh giá flag theo lifecycle, trạng thái cấu hình, group/flag kill switch, global on, ordered rules và default off.
    \item \textbf{Admin Dashboard}: hỗ trợ quản trị project, flag, rule, group kill switch, audit log, history, statistics và hiển thị trạng thái theo quyền người dùng.
    \item \textbf{Demo Application}: mô phỏng ứng dụng web tích hợp Feature Flag, gọi SDK để hiển thị hoặc ẩn tính năng theo kết quả evaluation.
    \item \textbf{JavaScript SDK}: cung cấp hàm \texttt{evaluate}, \texttt{isEnabled}, \texttt{getVariant}, validate response, xử lý timeout và fallback fail-closed.
    \item \textbf{Persistence và delivery}: dùng PostgreSQL, Prisma migration/seed, Jest/Supertest, GitHub Actions CI và Docker Compose cho môi trường chạy thử.
\end{itemize}

Các chức năng được hỗ trợ gồm global enable/disable, user allowlist, role targeting, percentage rollout, audit log append-only, audit-backed history, evaluation statistics, group kill switch, RBAC demo và cache snapshot evaluation. Những vấn đề production-scale như multi-region deployment, streaming SDK, approval workflow hoàn chỉnh, A/B testing nâng cao, monitoring hạ tầng chuyên sâu, backup/recovery và xử lý lưu lượng rất lớn được xem là hướng phát triển sau phạm vi mini project.
